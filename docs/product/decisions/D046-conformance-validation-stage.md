# D046 — Generation-rule conformance as validation stage 5

**Status:** Confirmed  
**Date:** 2026-11-18  
**Scope:** Snapshot validation. Approved from [TIMBER-001](../../implementation/tasks/TIMBER-001.md) §10, item 3.  
**Amends:** [D035](D035-validation-stages-detail-codes.md) (adds a fifth stage) and [D037](D037-error-related-paths.md) (adds mapping rows).

## Decision

Validation gains a **fifth stage, conformance**, after syntactic, referential, geometric, and domain:

- **What it checks:** every generated member must be exactly what the snapshot's generation rule produces: the same generation keys, roles, sections and materials (from `member_defaults`, [D039](D039-frame-member-defaults.md)), and endpoints within the D026 comparison epsilon of 1e-6 m per coordinate.
- **When it runs:** only when stages 1–4 pass. The rule is defined only for supported configurations, so a snapshot outside the supported domain reports its stage-4 issues and is never checked for conformance.
- **Top-level code:** `VALIDATION_FAILED`. A member that disagrees with its rule is invalid data, not an unsupported configuration. D035's principle holds: the top-level code is the first failing stage's code.

### New detail codes (stage 5)

| Detail code | Situation | `path` | `value` | `related_paths` |
|---|---|---|---|---|
| `MISSING_GENERATED_MEMBER` | The rule generates a key that no member has | `entities[<frame>].member_ids` | the missing key | — |
| `UNEXPECTED_MEMBER` | A member's key is not generated by the rule | `entities[<member>].generation_key` | the key | — |
| `MEMBER_GEOMETRY_MISMATCH` | `start_m` or `end_m` differs from the rule by more than 1e-6 m in any coordinate. Swapped endpoints count | `entities[<member>].start_m` or `.end_m` | — | — |
| `MEMBER_ASSIGNMENT_MISMATCH` | `member_role`, `section_id`, or `material_id` differs from what the rule assigns | `entities[<member>].<field>` | the stored value | for `section_id` and `material_id`: `entities[<frame>].member_defaults.<ROLE>.<field>` |

The last row's `related_paths` is a new D037 mapping row.

## Rationale

Without this stage, a snapshot could be valid while its members contradict its own parameters, which was MODEL-001's main limitation. Running conformance as its own stage, after domain checks, keeps each stage's top-level code meaningful. It also avoids checking members against a rule outside its supported domain.

## What this does not decide

- How the generator works: TIMBER-001 and generation-rules.md (including "Numeric evaluation").
- Conformance for future rule versions or for user-authored members. Each rule version supplies its own conformance check through the rule registry (TIMBER-001 §6).
