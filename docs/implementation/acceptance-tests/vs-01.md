# VS-01 — Scope and acceptance criteria

**Goal:** A working browser application that creates, edits, saves, and reloads a simple two-story timber-frame house, with synchronized 2D/3D views and a preliminary member schedule.

### In scope

- Create a new project from a fixed two-story rectangular reference-house template.
- Store explicit building footprint dimensions, floor elevations, roof pitch, and a regular timber grid.
- Generate basic posts and beams using deterministic parametric rules; no automatic structural adequacy claim.
- Display a 2D plan and 3D frame/building visualization derived from the same model.
- Edit footprint dimensions and observe regenerated dependent geometry.
- List timber members with stable IDs, nominal section, computed length, and quantities.
- Provide a preliminary quantity-based material-cost estimate only if unit costs are configured; otherwise display missing-cost status.
- Persist and reload the project and revision history.
- Automated tests for core geometry, revisions, invalidation, persistence, and view-model consistency.

### Explicitly out of scope

- Structural engineering certification or permit-ready outputs.
- Detailed joinery machining geometry or CNC output.
- Complete plumbing, electrical, HVAC design.
- Full energy simulation, lifecycle assessment, or jurisdictional code compliance.
- AI-driven edits, multi-user simultaneous editing, and professional sign-off.
- Arbitrary curved/irregular buildings.

### Acceptance criteria

**AC-01:** A user creates Reference House 001 from the template and sees the same dimensions in 2D and 3D.

**AC-02:** Changing the footprint width through a validated model operation updates dependent timber positions/lengths and both views without stale geometry.

**AC-03:** Every generated timber member has a stable ID and deterministic length/quantity computation for the same model revision.

**AC-04:** The timber schedule reconciles with the generated member inventory, and reports units and assumptions.

**AC-05:** Saving and reopening a project restores semantically equivalent building data, including its revision ID and parameter values.

**AC-06:** Invalid dimensions or contradictory constraints are rejected atomically with actionable errors.

**AC-07:** Derived geometry and schedules identify the revision they were computed from; stale outputs are not represented as current.

**AC-08:** The UI labels framing and estimates as preliminary, not structurally verified or construction-approved.

**AC-09:** Automated tests cover the operations and invariants above, including deterministic replay and serialization round-trips.
