# EST-001 — `timber_schedule` and `preliminary_estimate` derivations, and price books

**Status:** Implemented (2026-11-19). See §8 for implementation notes.  
**Owner modules:** `timber` (schedule), `estimating` (estimate, price books)  
**Slice:** VS-01  
**Depends on:** `ART-001` (derivation registry, envelope, storage, dependency order)  
**Unblocks:** `UI-001` (schedule and estimate views; AC-04, VS-01 scope "missing-cost status")  
**Closes:** C6 (POST aggregate split), M9 (price book), and the duplicate-label aggregation gap (D049)

## 1. Objective and user-visible behavior

- **The schedule:** derive the preliminary member schedule with reference-axis lengths that reconcile with the inventory (AC-03, AC-04).
- **The estimate:** derive a quantity-based estimate that is **`UNAVAILABLE` unless dated unit prices are configured**. It never reports a fabricated `$0` (D027, artifacts.md §8).
- **Price books:** add a minimal, versioned, per-project price book, so the "configured unit costs" path in VS-01 exists and can be tested.

## 2. Scope

**In scope**

- Pydantic payload models for both artifacts, added to `artifacts.v1.schema.json` (D028).
- `schedule-vs01` and `estimate-vs01` derivations registered with `ART-001`. The estimate runs after the schedule and reads the schedule of the **same revision**.
- **Price books:**
  - the schema (§5);
  - versioned, append-only storage per project (both stores);
  - `ProjectService.set_price_book(project_id, book, *, actor_id, now)` and `get_price_book(project_id)`;
  - the estimate fingerprint includes the book identity and version (artifacts.md §2.3).

**Non-goals:** licensed or sourced price datasets (open question 6, which stays open), labor, subcontractor, site, permit, or contingency categories (FR-08, later slices), embodied carbon, board-foot conversion (a UI concern), multiple currencies.

## 3. `timber_schedule` (proposed details — §7)

As artifacts.md §7, with:

- **Rows:** one row per stored `TimberMember`, sorted by `generation_key`.
  - `nominal_section` = `Section.nominal_label`;
  - `species` and `grade` from the member's `Material`; unknown values stay `null`;
  - `quantity` = 1.
- **Length:** `length_m` = `sqrt(dx*dx + dy*dy + dz*dz)`, where `d = end_m − start_m`, evaluated exactly as written. The naive formula is required so that every language produces the same bits. A library `hypot` or `math.dist` can differ in the last bit.
- **Aggregates:** one row per (`role`, `nominal_section`), which identifies exactly one section because labels are unique (D049). `count` and `total_length_m` are summed over the member rows **in `generation_key` order**. Rows are sorted by `role`, then `nominal_section`. Posts are **not** split by story (C6).
- **Assumptions:** `REFERENCE_AXIS_LENGTH` and `NO_CONNECTIONS` are always present.

## 4. `preliminary_estimate` (proposed details — §7)

As artifacts.md §8, with:

- **Line items:** one line item per schedule aggregate, with key `timber.<ROLE>.<nominal_section>` (as D027), `quantity_value` = the aggregate's `total_length_m`, and `quantity_unit` `m`. Lines are sorted by key.
- **Coverage:**

  | Book | Lines with a matching price | Status | Coverage | `grand_total_minor` |
  |---|---|---|---|---|
  | none | — | `UNAVAILABLE` | `none` | `null` |
  | present | some, not all | `CURRENT` | `partial` | `null` |
  | present | all | `CURRENT` | `complete` | sum of line amounts |

  `currency` is `null` when coverage is `none`. `COST_INPUTS_MISSING` is present when coverage is `none` or `partial`.
- **Money:** `amount_minor` = `unit_price_minor × quantity_value`, computed **exactly** from the double's exact binary value, then rounded to an integer with **round-half-even**. `priced_amount_minor` is the sum of the priced lines' amounts (`null` if none are priced). Totals are integers in minor units (D026).

## 5. Price book (approved — §7 item 4)

```json
{
  "currency": "USD",
  "as_of": "2026-11-01",
  "source": "Supplier quote #123",
  "geography": "Chittenden County, VT",
  "rows": [
    { "key": "timber.POST.8x8", "unit": "m", "unit_price_minor": 3150 },
    { "key": "timber.BEAM.8x12", "unit": "m", "unit_price_minor": 4725 }
  ]
}
```

- **Book-level metadata:** `currency`, `as_of`, `source`, and `geography` apply to every row. They are copied onto `price_book` in the estimate payload, together with `price_book_id` and `price_book_version`.
  - In VS-01, `currency` must be `USD`.
  - `as_of` is an ISO date.
  - `unit_price_minor` is a non-negative integer within ±(2⁵³ − 1).
  - Rows are unique by `key`, and `unit` is `m`.
  - Rows whose key matches no line item are ignored and listed in a warning, not rejected.
- **Storage:** `price_books (project_id, version, price_book_id, book jsonb, set_by, set_at)`.
  - Versions are append-only, so setting a book creates version n+1.
  - `price_book_id` is a UUIDv4 assigned on the first version and kept thereafter.
  - Clearing the book is not supported in VS-01.
- **Not part of the model:** setting a price book is **not** a model command. It creates no revision, because price books live outside the semantic snapshot (artifacts.md §8). The version row itself is the audit record. Setting a book makes the head's estimate `STALE` through its fingerprint, and `ART-001`'s lazy recompute then refreshes it. The other three artifacts are unaffected.

## 6. Acceptance criteria and automated tests

1. **Reference House 001 schedule:** 58 rows with the snapshot's IDs, and aggregates `BEAM 8x12: 34, 124.3584 m` and `POST 8x8: 24, 69.4944 m` within 1e-6 × n (artifacts.md §7). Counts and totals reconcile with the inventory (test 4, AC-04).
2. **No book:** the estimate is `UNAVAILABLE`, `coverage: none`, `currency: null`, `grand_total_minor: null` (never `0`), and the line quantities equal the schedule aggregates (tests 4 and 8).
3. **Partial book:** with only posts priced, the estimate is `CURRENT`, `partial`, `grand_total_minor: null`, with `COST_INPUTS_MISSING`.
4. **Complete book:** with both roles priced, the estimate is `complete`, and the grand total is an integer equal to the sum of the line amounts.
5. **Rounding vectors:** exact-half cases round to even. Typical amounts agree with exact decimal arithmetic.
6. **Book change:** setting a new version makes the head's estimate `STALE`, then `CURRENT` with a new fingerprint. The schedule, plan, and mesh keep their status.
7. **Unique labels (D049):** `AddSection` with an existing label is rejected (`DUPLICATE_SECTION_LABEL`), so a label always identifies one section in aggregates and price books.
8. **Recompute after a change:** after a width change, schedule lengths, aggregates, and estimate quantities are recomputed for the new head.
9. **Determinism:** identical revisions and books give byte-identical canonical payloads. A cross-language vector reproduces the Reference House 001 schedule.
10. **Contract:** both payloads validate against `artifacts.v1.schema.json`. Invalid books (wrong currency, negative price, duplicate key, bad date) are rejected with D035-style issues.

## 8. Implementation notes (2026-11-19)

**Delivered:**
- `backend/src/homedesign/timber/schedule.py`: `TimberSchedulePayload`, `build_schedule`, and the `SCHEDULE` derivation.
- `backend/src/homedesign/estimating/`:
  - `pricebook.py`: the `PriceBook` model and `validate_price_book`;
  - `estimate.py`: `PreliminaryEstimatePayload`, `build_estimate`, `amount_minor` (exact multiplication with half-even rounding), and the `ESTIMATE` derivation.
- Migration `0003_price_books.sql` (append-only), price-book methods on both stores, and `ProjectService.set_price_book` / `get_price_book`.
- Both derivations registered in the production registry, so every project now has all four artifacts.
- Both payloads and the price book added to `artifacts.v1.schema.json`.
- An independent ECMAScript schedule in `generate.mjs`, whose fingerprint and aggregates match Python exactly.

**Tests:** 383 pytest tests pass, 49 of them new, covering all §6 criteria:
- the Reference House 001 schedule: 58 rows, `BEAM 8x12: 34` and `POST 8x8: 24`, reconciling totals summed in key order, assumptions, species and grade;
- the plain length formula, and the cross-language schedule vector;
- no book (`UNAVAILABLE`, null totals, never 0, quantities equal to the aggregates), a partial book, and a complete book (amounts checked independently with `Fraction`);
- unused rows producing a warning;
- ten rounding vectors, including exact half cents and `5 × 0.1` → 1 (the binary value of 0.1 is just above 1/10);
- a book change making only the estimate `STALE` (no revision; book versions 1 → 2 with a stable ID);
- duplicate section labels rejected through the service (D049);
- a width change recomputing schedule and estimate;
- determinism, schema validation, and nine invalid-book cases;
- an unknown project, and append-only `price_books` (PostgreSQL).

**Choices made during implementation:**

- **Unhashed external context:** artifacts.md §2.3 fingerprints only the book's `price_book_id`, `price_book_version`, `as_of`, and `currency`, but the derivation also needs the rows. ART-001's `external_inputs` now passes keys starting with `_` to the derivation without fingerprinting them. Such keys must be fully determined by the fingerprinted ones, which holds here because book versions are append-only.
- **Price-book validation** follows D035 stage gating: shape and types (stage 1), then duplicate row keys (the new stage-2 code `DUPLICATE_PRICE_KEY`, added to building-model.md §6.1), then negative prices (`OUT_OF_RANGE`, stage 3). The mutation meta-test now lists `DUPLICATE_PRICE_KEY` as a code exercised outside snapshot validation.
- **New warning code:** `PRICE_ROWS_UNUSED` names book rows that match no line item. The rows are ignored, not rejected (artifacts.md §8.2).
- **Concurrent books:** setting a book locks the project row, so concurrent versions serialize.

**Limitations:**

- No HTTP endpoints for price books yet (API task).
- Clearing a book is unsupported, as decided.
- USD only.
- No labor, subcontractor, or other cost categories (FR-08 later slices).
