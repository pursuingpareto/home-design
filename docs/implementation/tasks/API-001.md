# API-001 — HTTP API for VS-01

**Status:** Done (2026-11-19) — see §13 for implementation notes  
**Owner module:** `api` (new): HTTP transport only, over `project` and `dependencies`  
**Slice:** VS-01  
**Depends on:** `MODEL-004`, `ART-001`, `GEOM-001`, `EST-001` (all done)  
**Unblocks:** `UI-001` (browser client)  
**Touches:** open question 8 (identity, security) only as far as VS-01 needs; production identity stays open

## 1. Objective and user-visible behavior

Expose the VS-01 service layer over HTTP at `/api/v1`, with the error envelope, status codes, authentication, and project-scoped authorization required by interfaces.md §2–9. After this task, a client can:

- create a project;
- preview and commit commands;
- read revisions, history, artifacts, and the manifest;
- set a price book;

all over HTTP, with every interfaces.md §9 contract test runnable against a real server.

No business logic lives here. Handlers parse, authenticate, authorize, call the services, and map results and errors.

**In scope**

- An audit-log read endpoint (later, with roles).

## 4. Routes (approved — §11 item 2)

| Method and path | Service call | Success |
|---|---|---|
| `POST /api/v1/projects` | `create_project` (creation envelope) | **201**, or 200 for a retry (`"replayed": true`) |
| `GET /api/v1/projects/{id}` | `get_project`, plus the caller's permissions | 200 `{project_id, head_revision_id, head_sequence, created_at, permissions: ["read", "write"]}` |
| `POST /api/v1/projects/{id}/commands/preview` | `preview` | 200: interfaces.md §3 body, including `preview_token` and `expires_at` |
| `POST /api/v1/projects/{id}/commands/commit` | `commit` with body `{command, preview_token?}` | **201** for a new revision; 200 for a no-op or retry |
| `GET /api/v1/projects/{id}/revisions` | `list_revisions` | 200 `{revisions: [...]}`, ordered by sequence |
| `GET /api/v1/projects/{id}/revisions/{rev}` | `get_revision` | 200: the snapshot |
| `GET /api/v1/projects/{id}/artifacts?revision_id=` | `manifest` (head if omitted) | 200: manifest |
| `GET /api/v1/projects/{id}/artifacts/{type}?revision_id=` | `get_artifact` | per artifacts.md §2.1, as below |
| `PUT /api/v1/projects/{id}/price-book` | `set_price_book` | **201** `{price_book_id, version, set_at}` |
| `GET /api/v1/projects/{id}/price-book` | `get_price_book` | 200 `{price_book: {...} \| null}` |

**Artifact responses** (artifacts.md §2.1 and §9):

| Status | HTTP | Body |
|---|---|---|
| `CURRENT` | 200 | envelope with payload |
| `UNAVAILABLE` | 200 | envelope, with partial payload when provided |
| `FAILED` | 200 | envelope with `error` |
| `MISSING` | 202 | envelope without payload; only for a type with no registered derivation, because `get_artifact` derives on read |
| unknown type or revision | 404 | error envelope |

- **No `503`:** VS-01 has no external dependency that can be unavailable.
- **Price books:** `PUT` is idempotent in effect, but not deduplicated. Every successful `PUT` creates a new version, which is the audit record. Clients that must not create duplicate versions read `GET` first.

## 5. Requests, errors, and request IDs (approved — §11 item 3)

- **Strict bodies:** JSON request bodies are parsed by the strict parser (`homedesign.model.strict_json`), not the framework's default JSON decoder. Duplicate keys, `NaN`/`Infinity`, and oversized or overly deep bodies are rejected exactly as for snapshots (MODEL-001 §5.1): HTTP 422 `VALIDATION_FAILED` with `MALFORMED_JSON`, `DUPLICATE_KEY`, `NON_FINITE_NUMBER`, or `PAYLOAD_LIMIT_EXCEEDED`. A wrong `Content-Type` is 415.
- **Error envelope** (interfaces.md §7): every error is `{"error": {"code", "message", "details", "request_id"}}`.
  - Each detail is `{path, code, value?, related_paths?}` from the service's `ValidationResult`; per-issue messages are left out.
  - The status comes from the typed service error:

    | Error | HTTP |
    |---|---|
    | `CommandRejected` | 422 |
    | `RevisionConflict`, `IdempotencyConflict`, `PreviewInvalid`, `PreviewExpired` | 409 |
    | `PreviewRequired` | 428 |
    | `NotFound` | 404 |
- **Request IDs:** every response carries `X-Request-ID`. The server generates a UUIDv4 for each request; a client-supplied ID is not trusted. The same ID is used as `request_id` in error bodies.
- **Unexpected errors:** any unexpected exception, including `CorruptRevision`, returns 500 `{"error": {"code": "INTERNAL", ...}}` with no stack trace, and is logged with its request ID and no project content (dependencies.md §9).

## 6. Authentication and authorization (approved — D050)

- **Authentication** is pluggable: an `Authenticator` maps a request to an actor UUID or rejects it.
  - VS-01 ships a single **development authenticator**: `Authorization: Bearer <token>`, with tokens mapped to actor UUIDs by server configuration.
  - A missing or unknown token is 401 `UNAUTHORIZED`.
  - The real identity provider replaces this authenticator when open question 8 is resolved, with no route changes.
- **Authorization** in VS-01: a project is readable and writable **only by its creator** (`projects.created_by`).
  - Any other authenticated actor gets **404 `NOT_FOUND`**, the same response as a project that does not exist, so a project's existence is not revealed (interfaces.md §9, test 6).
  - `403 FORBIDDEN` is reserved for later roles that can see a project but not change it.
- **Server-side identity:** the actor always comes from authentication, never from the request body (interfaces.md §2).

## 7. Configuration (approved — §11 item 6)

| Setting | Meaning |
|---|---|
| `HOMEDESIGN_DATABASE_URL` | PostgreSQL connection string. Required unless `HOMEDESIGN_STORE=memory` |
| `HOMEDESIGN_STORE` | `postgres` (default) or `memory` (development and tests only) |
| `HOMEDESIGN_PREVIEW_KEY` | Preview-token HMAC key, hex-encoded, at least 32 bytes. **The server refuses to start without it** (D047) |
| `HOMEDESIGN_DEV_TOKENS` | `token=actor-uuid,…` for the development authenticator |
| `HOMEDESIGN_CORS_ORIGINS` | Comma-separated browser origins allowed for `UI-001`. Empty by default |

Settings are read once into a typed settings object, and secrets are never logged. Migrations are not run on startup; they are applied with `python -m homedesign.project.migrate` (MODEL-004).

## 8. OpenAPI

The OpenAPI document is generated from the same Pydantic models as the services:

- command envelopes;
- the commit and preview results, which this task gives Pydantic response models;
- the snapshot;
- the artifact envelope, manifest, and payloads;
- the price book;
- the error envelope.

Request bodies are declared in OpenAPI but parsed strictly by the handler (§5). The document is committed as `docs/architecture/schemas/openapi.v1.json` and checked by `schema_export --check`. Generating and compiling the TypeScript client (interfaces.md §9, test 1, second half) is part of `UI-001`.

## 9. Acceptance criteria and automated tests

These run through an HTTP test client against both stores.

1. **The VS-01 flow end to end** (AC-01, AC-02, AC-05, AC-07, AC-08):
   - create Reference House 001;
   - read the manifest: plan, mesh, and schedule `CURRENT`, estimate `UNAVAILABLE`;
   - preview and commit a width change;
   - read `plan2d` and `mesh3d` for the new head: same `source_revision_id`, `preliminary` suitability, and the new width in both;
   - reload the revision by ID and get identical canonical bytes.
2. **Contract test matrix** (interfaces.md §9):
   - 1: OpenAPI is valid and examples validate against it;
   - 2: a preview writes nothing;
   - 3: a commit moves the head exactly once;
   - 4: two concurrent commits give one 201 and one 409 (PostgreSQL);
   - 5: a retry gives 200 `replayed` with no new revision;
   - 6: another actor gets 404 for every project route, and no token gets 401;
   - 7: plan, mesh, and schedule share `source_revision_id`;
   - 8: an unsupported geometry gives 422 `UNSUPPORTED_CONFIGURATION` with details.
3. **Error mapping:** one test per row of §5, including a body with a duplicate key, `NaN`, the wrong content type, `PREVIEW_REQUIRED` (428), an expired or invalid token (409), and an internal error (500 `INTERNAL`, no traceback).
4. **Artifact statuses:** `CURRENT`, `UNAVAILABLE`, `FAILED` (stub registry), and `MISSING` (empty registry, 202), each with the §4 status and body. An unknown type or revision is 404.
5. **Price books:** `PUT` then `GET`; the estimate becomes `STALE` in the manifest, then `CURRENT` on read; an invalid book is 422 with details.
6. **Request IDs:** every response has `X-Request-ID`, and error bodies repeat it.
7. **Startup:** the app refuses to start without `HOMEDESIGN_PREVIEW_KEY`, or with `postgres` and no database URL.

## 10. Implementation guidance (not prescriptive)

- **Layout:** `backend/src/homedesign/api/`: `app.py` (factory and exception handlers), `routes.py`, `auth.py`, `settings.py`, `models.py` (response and error DTOs).
- **Synchronous handlers:** psycopg is synchronous and each request makes a few short transactions.

## 13. Implementation notes (2026-11-19)

**Delivered** (`backend/src/homedesign/api/`):
- `settings.py`: `Settings.from_env()` for the §7 variables. `ConfigError` on a missing, non-hex, or short preview key, an unknown store, `postgres` without a URL, or a malformed token entry. Secrets are excluded from `repr`.
- `auth.py`: the `Authenticator` protocol and `DevTokenAuthenticator` (constant-time token comparison; 401 with `WWW-Authenticate: Bearer`).
- `body.py`: strict bodies. Reads are capped at the snapshot byte limit while streaming, then parsed by `strict_json` and scanned by the same parser-level checks as snapshots (duplicate keys, non-finite numbers, lone surrogates).
- `routes.py`: the ten §4 routes. Each authenticates, then authorizes with the new `ProjectService.require_owner` (D050) before reading the body or calling any other service. Services are synchronous and run in the thread pool.
- `app.py`: `create_app(settings=None, *, store, registry, authenticator, clock)`, the error envelope, request-ID middleware, CORS (only when origins are configured), and 500 `INTERNAL` for anything unexpected.
- `models.py` and `openapi.py`: response and request DTOs; the generated document is committed as `docs/architecture/schemas/openapi.v1.json` and checked by `schema_export --check`.

**Tests:** 436 pytest tests pass, 53 of them new in `tests/test_api.py`, all through an HTTP test client and against both stores where a store is involved. Every response a test receives is validated against the committed OpenAPI for its operation and status, and its `X-Request-ID` against the error body.
- §9.1: the VS-01 flow (manifest, preview, commit, `plan2d`/`mesh3d` at the new width with `preliminary` suitability, canonical bytes on reload).
- §9.2: contract tests 1–8. Test 4 runs three rounds of two concurrent commits on PostgreSQL, one client per thread. Test 6 checks all ten routes for another actor (404, byte-identical to a missing project apart from the request ID), no token and an unknown token (401), and that nothing was written.
- §9.3: duplicate keys, `NaN`, overflowing numbers, lone surrogates, malformed, empty, non-UTF-8, too-deep and too-large bodies, three wrong content types, the commit wrapper, every service error, unknown routes and methods, an injected exception, and a tampered revision (500 `INTERNAL`, nothing leaked to the body or the log).
- §9.4–9.7: artifact statuses with stub and empty registries, old revisions (`head: false`), price books, request IDs (server-generated, a client value ignored), startup checks, and CORS.
- **Live check:** uvicorn against a scratch PostgreSQL database served the §9.1 flow; the log contained no token or key.

**Choices made during implementation:**
- **Snapshots are served as their canonical bytes** (RFC 8785, entities sorted by ID; D029, D030), so a client can hash a revision response directly.
- **Commit-wrapper paths:** problems with the `{command, preview_token?}` wrapper are reported at body paths (`command` `MISSING_FIELD`, `preview_token` `WRONG_TYPE`, unknown keys `UNKNOWN_FIELD`). Paths inside the command stay relative to the envelope (`args.width_m`), the same as for preview (interfaces.md §7.1).
- **OpenAPI and docs are served at `/openapi.json` and `/docs`**, outside `/api/v1`, because every `/api/v1` route requires authentication. The document is public anyway (it is committed).
- **Logging:** an unexpected error is logged with its request ID, exception type, and stack frames (file, line, function). The exception message and source lines are left out, because they can quote project content.
- **Test client warning:** Starlette 1.10 recommends `httpx2` for its test client. The approved `httpx` 0.28 works; the deprecation warning is filtered in `pyproject.toml`.
